# Yemen Commerce Creator Console

The Creator Console is the separate Flutter/Dart management application for the system creator and explicitly delegated operators. It is intentionally separate from the customer and merchant application even though it uses the same Supabase project.

## Run locally

From the repository root:

```bash
cd creator_app
flutter pub get
flutter run -d chrome \
  --dart-define=SUPABASE_URL="$SUPABASE_URL" \
  --dart-define=SUPABASE_PUBLISHABLE_KEY="$SUPABASE_KEY"
```

Build the Web target with:

```bash
flutter build web --release \
  --dart-define=SUPABASE_URL="$SUPABASE_URL" \
  --dart-define=SUPABASE_PUBLISHABLE_KEY="$SUPABASE_KEY"
```

The Android and iOS targets are generated by Flutter and use the same Dart source. The current implementation is Web-first; mobile creator builds should be enabled only after the owner confirms the mobile release requirement and deep-link/MFA configuration.

## Access boundary

The app never uses a service-role key. It initializes Supabase with the public build-time key and calls creator-scoped RPCs. Supabase must verify the user’s `creator` role or explicit capability before returning dashboard data or allowing people-management actions. A public sign-up or client-side seed must never create a creator role.

The first creator account must be bootstrapped through a controlled administrative procedure in the intended Supabase environment, then verified with the synthetic-user negative-path tests. Delegated operators should receive explicit capabilities and optional market scope, expiry, and a reason.

## Current vertical slice

The current scaffold contains session gating, Arabic RTL styling, creator-only access checks, dashboard counters, people search, role delegation, account suspension/restoration actions, and placeholders for merchant governance, markets/policies, and audit/report views. The corresponding Supabase migration is `supabase/migrations/20260825_0005_creator_authorization.sql` plus `supabase/migrations/20260825_0006_creator_control_rpc.sql`.

## Shared packages

`packages/commerce_core` contains shared Supabase runtime configuration, Auth helpers, creator capabilities, and typed models. `packages/commerce_data` contains the creator-scoped Supabase repository. The customer/merchant app may depend on these packages, but creator-only screens and RPC methods must remain isolated from its feature modules.
