# Documentation Index

This directory contains the preparation artifacts for the Yemen Commerce Project. All documents are derived from the shared Ibb master plan and are intended to be reviewed before executable implementation begins. The master plan remains the governing baseline; the modular-expansion document records the additional project requirement that Ibb is an initial configuration rather than a hard-coded limit.

| Document | Purpose |
|---|---|
| [`product-requirements.md`](product-requirements.md) | Roles, customer and merchant requirements, fulfilment, status model, pilot metrics, and deferred scope. |
| [`design-brief.md`](design-brief.md) | Arabic-first UX direction, customer flow, payment-information page, cart communication, and accessibility requirements. |
| [`payment-policy.md`](payment-policy.md) | Merchant-owned payment posture, manual proof workflow, snapshots, status controls, and provider-integration gate. |
| [`architecture.md`](architecture.md) | Shared client, authoritative backend, storage, payment-adapter, security, and data-boundary decisions. |
| [`modular-expansion.md`](modular-expansion.md) | Modular architecture, configuration boundaries, extension contracts, and expansion-readiness criteria beyond Ibb. |
| [`data-model.md`](data-model.md) | Planned entities, relationships, invariants, state vocabularies, and retention questions. |
| [`api-contracts.md`](api-contracts.md) | Future resource groups, command/query outline, error categories, and contract rules. |
| [`delivery-plan.md`](delivery-plan.md) | Phased delivery sequence, backlog themes, decision register, and open decisions. |
| [`implementation-boundaries.md`](implementation-boundaries.md) | Explicit separation between preparation artifacts and deferred executable work. |

The governing source remains [`../Master Plan_ Ibb Commerce Platform for Mobile and Web.md`](../master-plan-mobile-web.md). If a later decision conflicts with that file, stop and resolve the conflict before implementation.
