## Flutter implementation

The customer/merchant Flutter app now has typed contracts and repository methods for service areas, pickup points, private customer addresses, delivery zones, product variants, order cases, notifications, reviews, promotions, storefront settings, inventory locations, audited inventory adjustments, atomic inventory transfers, stock counts, barcode-aware products, bounded bulk catalog import, merchant analytics, delivery-aware checkout, retry-safe checkout, server-side promotion application, COD collection, merchant quality, support tickets, provider catalog metadata, B2B business profiles/wholesale requests and merchant price-list review, courier dispatch handoff events, POS operations, B2B/POS aggregate analytics, and bounded CSV export. Checkout failures now persist an idempotent non-financial command into a user-scoped encrypted outbox, and the customer app exposes a sync center with sanitized diagnostics, pending/failed/blocked states, retry, confirmed discard, attempt counts, masked command identifiers, and privacy-safe error messaging. The foreground app listens for connectivity changes, while Android/iOS use a WorkManager best-effort periodic and connectivity-constrained one-off task; Web remains session/network/manual driven. Replay has a process-wide mutex, serialized per-scope secure-storage operations, server-side idempotency for checkout, promotion, and inventory commands, and never includes payment finalization, payment proof, or fund movement. Transient transport failures remain retryable, while authorization, validation, stock-conflict, and other business-rule failures become persistently blocked instead of entering an automatic retry loop. The customer UI includes an address book, notification inbox, address/pickup/zone selection at checkout, support-ticket creation, order cancellation/return/dispute request flow, and merchant workspace catalog/product creation. The merchant workspace now includes an Arabic-first inventory card for location setup, quantity adjustments, multi-product atomic transfers with bounded line authoring, cycle counts, barcode capture through the device camera, and a 500-row CSV import path with server-side validation and idempotency. Camera permissions are declared for Android and iOS, while browser camera permission remains a runtime requirement on Web. The merchant workspace now surfaces aggregate insights, explainable quality metrics, provider catalog configuration in preview/manual states, promotion drafts, advanced-services previews, server-controlled COD collection, courier dispatch handoff actions, B2B wholesale request review and price-list drafts, B2B funnel/pricing analytics with CSV export, and POS session/sale recording with structured line items, close/match controls, reconciliation analytics, and CSV export. The Creator Console includes provider, trust/support, and live market-operations pages for service-area and pickup-point governance. These screens never send messages, create provider shipments, verify payments, move funds, publish to external channels, or activate a provider without a server-side approval path.

## Validation

The final Supabase Security Advisor returned no lints after migrations 0027 through 0032. Performance Advisor no longer reports the legacy or new unindexed foreign-key findings, and it reports no multiple-permissive-policy findings; it now reports 141 informational unused-index findings, including the newly created inventory FK and command-key indexes that have not yet accumulated production query usage. These are not grounds for immediate removal because the indexes were added for referential checks, RLS joins, and future operational queries; review them after representative traffic and query-plan measurements. The anonymous authorization runner covers the analytics/export RPCs, idempotent checkout/promotion RPCs, inventory location/adjustment/transfer/count/bulk-import/barcode RPCs, and the creator, provider, address, variant, order-case, courier, review, promotion, and notification RPCs, plus protected creator tables. Authenticated synthetic customer, merchant, review-agent, support-agent, and creator checks remain skipped until isolated access tokens or an isolated test project are supplied. Customer/Creator Console analysis/tests and production Web builds remain the required validation gates; Android/iOS device and archive validation are still platform-toolchain gates.
