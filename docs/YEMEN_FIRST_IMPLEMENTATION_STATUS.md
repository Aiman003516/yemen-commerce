## Increment C — B2B and Scale

Increment C adds an append-only, versioned B2B quote workflow. Merchants can edit price-list lines through server-authorized RPCs, select a merchant-owned wholesale request, create a new immutable quote version with product-name and price snapshots, and view the latest version. Customers receive a scoped quote inbox, can accept a sent version, and can apply an accepted version only to an awaiting-payment order from the same shop; the server still verifies line identity, quantities, validity, and order editability. Existing multi-merchant checkout splitting remains unchanged, and negotiated pricing never becomes a platform balance or custody mechanism.

Daily merchant rollups aggregate operational counts and totals by shop and business date. The app exposes a refreshable Arabic summary without customer identity, payment proofs, or provider secrets. Product catalog images now have a deterministic cross-platform optimizer that corrects orientation, caps the longest edge, emits JPEG, uploads under a user-namespaced private `product-assets` path, registers metadata, and marks the variant ready only through a completion RPC. The optimizer is deliberately not used for identity evidence or payment proofs.

The provider adapter framework exposes operation readiness and compliance notes while every operation remains disabled by default. Preview/manual provider pages remain non-executing; credentials, webhook verification, consent, settlement, refund behavior, terms, and compliance approval are prerequisites for any future adapter activation.

## Flutter implementation

The customer/merchant Flutter app now has typed contracts and repository methods for service areas, pickup points, private customer addresses, delivery zones, product variants, order cases, notifications, reviews, promotions, storefront settings, inventory locations, audited inventory adjustments, atomic inventory transfers, stock counts, barcode-aware products, bounded bulk catalog import, merchant analytics, delivery-aware checkout, retry-safe checkout, server-side promotion application, COD collection, merchant quality, support tickets, provider catalog metadata, B2B business profiles/wholesale requests and merchant price-list review, courier dispatch handoff events, POS operations, B2B/POS aggregate analytics, and bounded CSV export. Checkout failures now persist an idempotent non-financial command into a user-scoped encrypted outbox, and the customer app exposes a sync center with sanitized diagnostics, pending/failed/blocked states, retry, confirmed discard, attempt counts, masked command identifiers, and privacy-safe error messaging. The foreground app listens for connectivity changes, while Android/iOS use a WorkManager best-effort periodic and connectivity-constrained one-off task; Web remains session/network/manual driven. Replay has a process-wide mutex, serialized per-scope secure-storage operations, server-side idempotency for checkout, promotion, and inventory commands, and never includes payment finalization, payment proof, or fund movement. Transient transport failures remain retryable, while authorization, validation, stock-conflict, and other business-rule failures become persistently blocked instead of entering an automatic retry loop. The customer UI includes an address book, notification inbox, address/pickup/zone selection at checkout, support-ticket creation, order cancellation/return/dispute request flow, and merchant workspace catalog/product creation. The merchant workspace now includes an Arabic-first inventory card for location setup, quantity adjustments, multi-product atomic transfers with bounded line authoring, multi-product cycle counts with duplicate and quantity validation, barcode capture through the device camera, and a 500-row CSV import path with server-side validation and idempotency. The Sync Center includes a sanitized detail view for blocked and retryable commands with explicit next-step guidance. Camera permissions are declared for Android and iOS, while browser camera permission remains a runtime requirement on Web. The merchant workspace now surfaces aggregate insights, explainable quality metrics, provider catalog configuration in preview/manual states, promotion drafts, advanced-services previews, server-controlled COD collection, courier dispatch handoff actions, B2B wholesale request review and price-list drafts, B2B funnel/pricing analytics with CSV export, POS session/sale recording with structured line items, close/match controls, reconciliation analytics, and CSV export. Increment B adds an Arabic-first merchant Order Workbench with bounded search/status filters and non-PII operational projections, plus a COD batch-management screen for daily opening, append-only collection recording, latest-record summaries, variance display, server-authorized close, and safe refresh/error states. Fulfilment actions use the existing payment-before-fulfilment RPC; the UI never writes order status or payment evidence directly. The Creator Console includes provider, trust/support, and live market-operations pages for service-area and pickup-point governance. These screens never send messages, create provider shipments, verify payments, move funds, publish to external channels, or activate a provider without a server-side approval path.
